# NS26F Telemetry Dashboard

NS26F 데이터로거의 CSV 로그를 브라우저에서 분석하는 독립형 정적 웹 프로젝트입니다.

## 로컬 실행

macOS에서는 `대시보드_실행.command`를 더블클릭하거나 아래 명령을 실행합니다.

```bash
python3 -m http.server 8081
```

그다음 <http://localhost:8081>을 엽니다.

## Vercel 배포

```bash
npx vercel --prod
```

CSV는 서버에 저장하지 않고 브라우저에서 직접 파싱합니다.

## 주요 파일

- `index.html`: 페이지 구조
- `style.css`: 화면 스타일
- `app.js`: CSV 파싱, EMU CAN 해석, 차트 및 GPS 기능
- `filters.js`: 채널별 노이즈 필터 (DSP 커널 + 우클릭 메뉴 UI)
- `steering.js`: 조향 영점 보정 (자동 추정 + 핸들 위젯 패널)
- `realtime.js`: 5번 탭 실시간 무선 텔레메트리 (수신·판정·실시간 차트)
- `tools/rf_bridge.py`: RF 수신 PC에서 돌리는 중계 서버
- `vercel.json`: Vercel 정적 배포 설정

## 실시간 무선 텔레메트리 (5번 탭)

```text
차량 ──RF(LoRa)──▶ 수신 PC(rf_bridge.py) ──WebSocket──▶ 팀원들의 브라우저
```

이 사이트는 정적 페이지라 자체 서버가 없습니다. RF를 받는 PC가 중계 서버를 띄우고,
팀원들이 5번 탭에 그 주소를 넣으면 전원이 같은 값을 실시간으로 봅니다.

### 수신 PC에서

```bash
# 실제 RF 수신기 연결
python3 tools/rf_bridge.py --serial /dev/tty.usbserial-0001 --baud 115200

# 장비 없이 시험 (가짜 데이터)
python3 tools/rf_bridge.py --sim

# 기존 로그를 실시간처럼 재생
python3 tools/rf_bridge.py --replay telemetry_20260801_095829.csv
```

표준 라이브러리만 씁니다(시리얼 입력에만 `pip install pyserial` 필요).
실행하면 접속 주소를 직접 출력해 줍니다. 같은 와이파이가 아니라면 터널을 하나 띄우세요.

```bash
cloudflared tunnel --url http://localhost:8765     # 또는  ngrok http 8765
```

### 팀원 브라우저에서

5번 탭 → 주소 입력(`ws://192.168.0.10:8765`) → **연결**.
하드웨어 없이 화면만 보려면 **데모 모드** 버튼을 누르면 됩니다.

전송 방식은 주소를 보고 자동 판별하며(WebSocket / SSE / HTTP 폴링), 연결이 끊기면
1초→15초로 간격을 늘려가며 자동 재연결합니다. 채널은 수신 데이터에서 자동 감지되므로
나중에 항목을 추가해도 카드가 알아서 생깁니다.

### 수신감도 6단계 판정 기준

실제 RF 로그(`telemetry_20260801_095829.csv`, 8,300패킷)에서 seq 연속성으로 패킷 손실을
계산하고 RSSI/SNR과 대조해 정했습니다. **SNR이 RSSI보다 훨씬 좋은 예측 지표**였고,
SNR 3dB / RSSI −105dBm 부근에 손실률이 급격히 꺾이는 절벽이 있었습니다.

| 등급 | 실측 손실률 | SNR | RSSI | 5초창 손실률 실측(중앙값/p90) |
| --- | --- | --- | --- | --- |
| 아주좋음 | < 2% | ≥ 8 dB | ≥ −95 dBm | 0.0% / 4.0% |
| 좋음 | 2~5% | 6~8 dB | −100~−95 | 0.0% / 8.3% |
| 보통 | 5~15% | 3~6 dB | −105~−100 | 0.0% / 23.9% |
| 나쁨 | 15~30% | 0~3 dB | −110~−105 | 16.7% / 45.7% |
| 아주나쁨 | ≥ 30% | < 0 dB | < −110 | 24~35% / 54~70% |
| 신호없음 | 3초 이상 무수신 | — | — | — |

최종 등급은 **세 지표 중 가장 나쁜 값**입니다. 링크가 무너지기 직전을 미리 알리기
위해 보수적으로 판정합니다. 무수신 기준 3초는 공칭 수신 주기(236ms, 4.2Hz) 대비
실주행 중 3초 이상 공백이 전체의 0.1~0.22%뿐이라 오탐이 거의 없는 값입니다.

### 수신 PC가 보내야 하는 형식

한 줄에 하나씩, 아래 중 아무 형식이나 됩니다.

```text
{"msg_type":"FAST","seq":12,"rpm":5200,"tps_pct":31.5,"rssi":-72,"snr":9.4}

#msg_type,seq,rpm,tps_pct,rssi,snr        ← 헤더를 한 번 먼저
FAST,12,5200,31.5,-72,9.4
```

`seq`가 있으면 패킷 손실을 자동 계산하고, `rssi`/`snr`이 있으면 감도 판정에 씁니다.
`msg_type`이 다르면(FAST/SLOW) 시퀀스를 따로 추적합니다.

## 조향 영점 보정

핸들 그래픽의 **⚙ 버튼**을 누르면 보정 패널이 열립니다. (2페이지에서는 핸들 전체 클릭)

```text
조향각[°] = (raw − 영점raw) × 배율[°/LSB] × (반전 ? −1 : +1)
```

- **자동 영점 추정** 버튼이 서로 독립적인 두 가지 방법으로 영점을 계산합니다.
  - *분포 기반*: 고속 + 조향 변화율이 낮은 직진 구간의 조향 raw 최빈값
  - *GPS 궤적 검증*: GPS 위치에서 요레이트를 구해 자전거 모델
    (요레이트/속도 ∝ 조향각)로 회귀 → 요레이트가 0이 되는 raw 값.
    **조향 센서 값과 전혀 무관한 독립 측정**이라 교차검증에 씁니다.
  - 두 값의 차이가 3° 이내면 일치 판정을 표시하고, 크면 경고합니다.
- **현재 커서를 0°로**: 직진 구간에 커서를 놓고 누르면 그 지점이 영점이 됩니다.
- 보정값은 브라우저에 저장되어 다음 접속에도 유지됩니다. 원본 CSV는 바뀌지 않습니다.
- 배율을 키워 조향각이 기본 범위(±250°)를 넘으면 Y축이 자동으로 확장됩니다.

### Telemetry_001.csv 기준 확인 사항

기존 하드코딩 식(`(raw−2048)×0.1+105`, 실효 영점 raw 998)으로는 **직진 주행 중에도
조향각이 +28.9°로 표시**됩니다. 두 추정 방법이 모두 영점을 raw 1287~1305로 지목했고
(차이 1.8°), GPS 회귀의 상관계수는 r=0.83이었습니다. 실주행 로그를 열고 자동 추정을
한 번 돌려보길 권장합니다.

> 기본값(영점 998 / 배율 0.1 / 반전 없음)은 기존 식과 수치적으로 완전히 동일하므로,
> 아무것도 건드리지 않으면 이전과 똑같이 보입니다.

## 노이즈 필터 사용법

아무 그래프 위에서 **우클릭**하면 그 그래프가 그리는 채널의 필터 메뉴가 열립니다.

- 한 그래프에 여러 채널이 있으면 메뉴 상단에서 채널을 고릅니다.
- 파라미터를 움직이면 그래프가 즉시 갱신됩니다.
- **추천 설정 적용**을 누르면 실주행 로그 분석으로 검증된 기본값이 들어갑니다.
- 필터가 걸린 그래프는 라벨바에 `⚡ MED 5` 같은 배지가 표시됩니다.

필터는 원본 100Hz 데이터에 적용된 뒤 화면용으로 다운샘플링되며, 업로드한 CSV
파일 자체는 절대 변경되지 않습니다. 기본값은 항상 **원본(Raw)** 이라 아무것도
누르지 않으면 로그에 기록된 값이 그대로 보입니다.

### 제공 필터

| 필터 | 용도 | 파라미터 |
| --- | --- | --- |
| 중앙값 (Median) | 순간적으로 튀는 값·드롭아웃 제거, 계단 보존 | 창 크기 |
| Hampel | 이상치만 골라 교체(평활 없음). RPM 급등 등 CAN 오류에 최적 | 창 크기, n·σ |
| 이동 평균 | 단순 평활 | 창 크기 |
| Savitzky-Golay | 피크 높이를 보존하는 평활 | 창 크기, 차수 |
| 버터워스 저역통과 | 차단주파수 기준 정통 LPF (위상 지연 없음) | 차단주파수, 차수 |
| EMA | 실시간 로거 필터와 동일한 특성(지연 있음) | 차단주파수 |
| 변화율 제한 | 물리적으로 불가능한 급변을 잘라냄 | 최대 변화율 |
| 드롭아웃 제거 | 유효범위를 벗어난 값(주로 0)을 보간 | 유효범위, 최대 보간 길이 |

### 실주행 로그(Telemetry_001.csv) 분석으로 확인된 사항

- **RL 휠속도**에 주행 중 0으로 떨어지는 드롭아웃이 3.5% 존재. 100km/h에서
  10~20ms만 0이 되었다 복귀하는 물리적으로 불가능한 패턴이며, 드롭아웃을
  보정하면 독립 센서(EMU VSS)와의 상관계수가 0.905 → 0.986으로 상승.
  ⇒ 이 채널만은 **드롭아웃 제거를 켜는 것을 권장**합니다.
- 서스펜션·조향·브레이크 신호는 전력의 95~99%가 2Hz 이하. 5Hz 저역통과 시
  peak-to-peak가 100.1% 보존되어 실제 거동 손실 없이 노이즈만 제거됩니다.

## 알려진 버그 수정 (2026-08-02)

`Papa.parse`의 `dynamicTyping: true`가 CAN 프레임 16진수 문자열을 숫자로
변환하면서 **전체 CAN 프레임의 3.85%(16,096개)가 손상**되고 있었습니다.

```text
'9E01082950004002' → 9e1082950004002 → Infinity → 'Infinity' → '000000000000000f'
'9402650000000001' → 2^53 초과로 하위 바이트 손실 → '9402650000000000'
```

그 결과 기어 10.1%, ECU 온도 11.4%, RR 서스펜션 3.1%의 샘플이 잘못 표시되고
있었고, 흡기온이 -112°C로 찍히는 현상도 이 문제 때문이었습니다. CAN 컬럼만
문자열로 유지하도록 수정했습니다.
